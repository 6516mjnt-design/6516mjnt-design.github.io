GitHub 導入ガイド

2026年8月1日更新

1. エグゼクティブ・サマリー

アカウント作成からリポジトリ管理、GitHub Desktopの活用、チームでのブランチ運用・プルリクエストまで、個人およびチームでの実践的なGit/GitHub活用プロセス。

  • ステップバイステップ設計：
    アカウント登録・Web操作から、GUIツール（GitHub Desktop）やCLI環境へのスムーズなステップアップ構造。
  • 安全なチーム開発の実践：
    main ブランチを守るための「ブランチ作成 → プルリクエスト → レビュー → マージ」ワークフローの徹底。
  • 同期と競合防止：
    作業開始時の Fetch/Pull origin や不要ブランチの削除による、常に最新・清潔なコードベースの維持。

2. 背景：GitHub利用手順の全貌

GitHubの導入から高度な活用法までの全体像と各段階の役割です。

フェーズ 操作・タスク 主要な機能・コマンド 目的・主な役割
第1段階 アカウント作成 Sign up, メール認証 GitHubの各種サービス・Web機能の利用準備
第2段階 リポジトリ作成 New repository, Public/Private コードやプロジェクトファイルを安全に保管・共有
第3段階 Web上での編集 Create new file, Commit changes Git操作なしで手軽にファイル更新・記録
第4段階 ローカルPC連携 GitHub Desktop / Git CLI PC上の開発環境とリモート保管庫を相互同期
リポジトリは「コードの保存庫」。チーム開発では直書きせず、自分専用の「ブランチ」を作って安全に作業するのが鉄則。

3. アカウント作成とリポジトリの準備

アカウント登録から最初の保存庫（リポジトリ）構築までの詳細手順です。

1. GitHubアカウントを作成する

  1. GitHub公式サイト にアクセスし、「Sign up」をクリックします。
  2. メールアドレス、パスワード、ユーザー名（GitHub上での表示名）を入力します。
  3. 登録したメールアドレスに送られてくる認証コードを入力すればアカウント作成完了です（無料プランで十分活用できます）。

2. リポジトリ（保存庫）を作成する

  1. ログイン後、画面右上にある「+」アイコンをクリックし、「New repository」を選択します。
  2. Repository name にプロジェクト名（例: my-first-project）を入力します。
  3. 公開設定を選びます：
    • Public： 誰でも閲覧可能（ポートフォリオや学習記録向け）
    • Private： 自分や招待した人だけが閲覧可能（非公開の練習・仕事向け）
  4. 「Add a README file」にチェックを入れる（概要説明ファイルが自動作成されます）。
  5. ページ下の「Create repository」ボタンを押すと、リポジトリが作成されます。

3. 最初のファイルをWeb上で作成・編集してみる

  1. 作成したリポジトリの画面で「Add file」→「Create new file」を選択します。
  2. ファイル名（例: index.html や README.md）を入力し、下のテキストボックスにコードや説明文を書きます。
  3. 編集が終わったら、右上の「Commit changes...」ボタンを押します。
  4. 変更メッセージ（例: 初回ファイルの追加 など）を入力し、再度「Commit changes」をクリックすれば保存（コミット）完了です。

4. 実践：ローカルPC環境との連携

本格的に自分のパソコン（ローカル環境）でコードを書いてGitHubに送信する方法です。

初学者におすすめ：GitHub Desktop

コマンド操作を使わず、画面上のマウス操作だけでGitHubへのアップロード（Push）や取り込み（Pull）ができる公式ソフトです。（desktop.github.com から入手可能）

コマンド（ターミナル / Git CLI）で操作する場合

1. PCに Git (https://git-scm.com/) をインストールします。
2. ターミナルで `git clone [リポジトリのURL]` を実行してPCにダウンロードします。
3. 編集後、`git add .` ➔ `git commit -m "メッセージ"` ➔ `git push` の順で送信します。

5. GitHub Desktop による基本ワークフロー 4ステップ

GitHub Desktopを使って日常的に共有・更新を行う基本の流れです。

  1. Step 1: アプリ準備・ログイン（初期設定）
    公式サイトからインストール後、アプリを起動し「Sign in to GitHub.com」をクリックしてブラウザでログイン認証を行います。
  2. Step 2: リポジトリをPCにダウンロード（Clone）
    「Clone a repository from the Internet...」を選択し、作業したいリポジトリと保存先（Local path）を確認して「Clone」を押します。
  3. Step 3: ファイルの追加・編集
    「Show in Finder / Explorer」で専用フォルダを開き、ファイルを保存・編集します。アプリに戻ると変更が自動で検出されます。
  4. Step 4: 変更の記録と送信（Commit & Push）
    画面左下にタイトル（例：トップページを作成）を入力して「Commit to main」を押し、最後に画面上の「Push origin」を押して送信完了です。

6. 複数人でのチーム開発とブランチ運用

本番コード（main）を直接書き換えず、安全にチームで開発を進める手順です。

1. 新しいブランチ（Branch）を作成する

本番コードに影響を与えない自分専用の作業スペースを作ります。

  1. 画面上の「Current Branch」をクリックし、右上の「New Branch」を押します。
  2. 作業内容がわかる名前（例: feature-add-header や fix-login-bug）を入力し、「Create Branch」をクリックします。
  3. 「Publish branch」ボタンが表示されたらクリックしてWeb上にも送信します。

2. ファイルを編集してコミット・プッシュする

PC上のフォルダでファイルを編集・保存後、GitHub Desktopでメッセージを入力して「Commit to [ブランチ名]」➔「Push origin」を押します。

3. プルリクエスト（Pull Request）を作成する

  1. 「Create Pull Request」という青いボタンをクリックしてブラウザを開きます。
  2. 「何を」「なぜ」変更したかをタイトルと説明文に記載します。
  3. 必要に応じて右側の「Reviewers」に確認メンバーを指定し、「Create pull request」を押します。

4. レビュー・マージ（Merge）を行う

  1. メンバーの確認後、問題がなければGitHub画面上の「Merge pull request」➔「Confirm merge」をクリックして main へ合体させます。
  2. 使い終わったブランチは「Delete branch」ボタンで削除して整理します。
  3. GitHub Desktopに戻り、「Current Branch」を main に切り替えて「Fetch origin（または Pull origin）」を押し、最新コードをダウンロードします。

7. 潜む 3つの危険な罠（注意点）

チーム開発でミスを防ぐために気を付けるべきポイントです。

① mainブランチでの直接作業（Direct Commit on Main）

ブランチを切らずに main を直接変更すると、動作確認前のコードで本番環境が破損したり、他の人の作業と激しく競合する原因になります。

② Fetch/Pullの失念による競合（Stale Local Branch）

作業を開始する前にリモートの最新状態を取り込まないと、古いコードをベースに作業してしまうことになり、マージ時に複雑なコンフリクト（衝突）が発生します。

③ 肥大化したプルリクエスト（Giant Pull Request）

複数の変更や巨大な修正を1つのプルリクエストに詰め込むと、レビュアーの負担が激増し、不具合の見落としに繋がります。「1タスク1プルリクエスト」を徹底しましょう。

8. まとめ

GitHub活用の要点は「小さなコミット」と「ブランチを使った安全な運用」にあります。まずはWeb上やGitHub Desktopで基本操作に慣れ、チーム開発でのプルリクエスト運用へと段階的に移行していくことで、安全で効率的なコード管理を実現できます。
