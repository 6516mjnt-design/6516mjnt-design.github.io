AIと暗号解読の動向（時系列）

作成日: 2026年10月4日時点の公開情報
主な出典: Matthew Green氏ブログ、Schneier on Security、The Hacker News、PostQuantum.com ほか（末尾に一覧）
2019年～2022年

機械学習による暗号解読の萌芽

2019年、Gohr氏がブロック暗号 Speck32/64 に対し、ニューラルネットで暗号文ペアの識別と鍵回復の効率化を示した。ResNet ベースのモデルが従来の機械学習手法を上回った。

2022年には SALSA が発表された。Transformer に剰余算を学習させ、統計的な解析手法と組み合わせて、格子暗号の基礎である LWE 問題を攻撃する手法である。ただし当時は、現実の LWE 暗号を攻撃できるとは主張されていなかった。

2023年～2025年

格子暗号（LWE）への機械学習攻撃の改良

2023年に SALSA VERDE（疎な小さい秘密鍵向け）と Salsapicante（二値の秘密鍵向け、ACM CCS '23）が続いた。2024年の Salsa Fresca は改良を示したが、著者らは現行の標準方式を脅かさないとしている。

2025年10月には、モジュラー LWE に対する非モジュラー攻撃 NoMod が arXiv に掲載された。2025年後半、Anthropic のレッドチームは、スマートコントラクトの攻撃コードを約1.22ドルの API 費用で生成できることを示した（暗号そのものではなく、実装・コードの脆弱性の話）。

2026年4月～7月上旬

実装バグ発見への展開と、慎重論

4月5日: Ledger の CTO が、AI は暗号そのものを破っているわけではないと警告した。懸念は、AI が生成する脆弱なコードが増えることにある。

5月14日: HAWK が NIST の追加署名方式の第3ラウンドに進んだ。格子ベースでは唯一の候補だった。

7月7日: zkSecurity の調査チームが AI による監査を Cloudflare の暗号ライブラリ CIRCL に適用し、7件の実際のバグを確認した。すべて修正済みである。

2026年6月～7月29日

転機：AIが数学的な暗号解析で成果を出す

6月: Anthropic が HAWK チームに通知した（HAWK 開発側も結果の検証に協力したとされる）。

7月28日: Anthropic が、未公開モデル Claude Mythos Preview による2つの成果と、評価用ベンチマーク CryptanalysisBench を公表した。論文では、モデルが既知の結果の導出にとどまらず、SpoC AEAD の設計上の欠陥を突く鍵回復攻撃なども生成したと報告されている。

1. HAWK（NIST の PQC 署名候補） 格子暗号

約60時間で欠陥を発見。2年間・2ラウンドの専門家レビューを通過していたとされる。格子構造の自己同型という対称性を突く攻撃で、完全な鍵回復の対象は、実運用のパラメータではなくチャレンジ用の HAWK-256 だった。

2. 7ラウンド AES 共通鍵暗号

「Möbius Bridge」という手法で、既存の最良の攻撃を200〜800倍高速化した。ただし 2105 の選択平文を要する研究用の想定で、10ラウンドの完全な AES には影響しない。

⚠️ 留意点： いずれも実運用中のシステムには影響しない。HAWK は未標準化の候補、AES は段数を減らした研究用の構成である。

7月29日: HAWK チームは、攻撃でブロックサイズが約半分になると確認し、NIST の標準化プロセスから撤回した。パラメータを倍にする対策では競争力を失うため、撤回を選んだとされる。NIST は同日、候補ページを更新した。同日、Matthew Green 氏は、AI が既存の暗号解析を理解し、新しい攻撃に統合し、拡張できるようになったと整理した。一方で「まだ超人的な暗号解読ではない」とも述べている。

2026年8月～10月

余波と対応論

9月4日: PostQuantumSecurity.org が整理記事を公開した。NIST は、HAWK の件が最終化済みの PQC 標準に影響しないと明確化したとのこと。ML-KEM、ML-DSA、SLH-DSA、Falcon、実運用の AES への影響はないとする解説もある。

9月上旬～中旬: 別の脆弱性として、LLM API が返す暗号化された推論ブロックが、暗号を破らずに別の文脈へ転用され、内部の推論内容が再構成されたと報じられた。暗号の強度とシステム全体の安全性は別問題だという論点である。

10月2日: 暗号アジリティ（アルゴリズムを素早く差し替える能力）の議論が広がっている。暗号の部品表（CBOM）で、どのシステムがどのアルゴリズムに依存するかを把握することが重要だと報じられた。

現時点での見方

確認されていること

AI が実運用中の暗号を破った事例は確認されていない。報告されているのは、未標準化の候補方式と、ラウンド数を減らした AES である。

変わりつつあること

問題の中心が、攻撃の発見から検証へ移りうるという見方が出ている。標準化審査に AI を組み込むべきだという議論もある。
